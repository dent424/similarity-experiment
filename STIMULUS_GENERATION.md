# Stimulus Generation Agent

This project uses Claude Code to generate product descriptions for a similarity judgment experiment. The workflow is designed to minimize hallucination through structured automation and verifiable data handling.

## How It Works

Run `/generate-stimulus-set [column-name] [word-limit]` to generate descriptions for all 29 products.

Example: `/generate-stimulus-set 50_word 50`

## Safeguards Against Hallucination

### 1. Slash Command as Orchestrator

The `/generate-stimulus-set` command enforces a fixed, repeatable process:

1. **Check** if the column already exists (prevents overwrites)
2. **Read** product data from the canonical CSV source
3. **Generate** descriptions via parallel sub-agents
4. **Write** results back to CSV
5. **Export** to JSON for the experiment

The agent cannot skip steps or improvise the workflow.

### 2. Python Scripts Handle All Data

Claude never directly reads or writes the CSV. Instead, `scripts/read_products.py` provides three verified operations:

```bash
python scripts/read_products.py check [column]  # Check if column exists
python scripts/read_products.py read            # Read product metadata
python scripts/read_products.py write [column] '{...}'  # Write descriptions
python scripts/read_products.py export [column] [limit] # Export to JSON
```

This ensures:
- Product IDs (ASINs) come from the source CSV, not generated
- Prices come from the source CSV, not generated
- Study names come from the source CSV, not generated
- Only descriptions are generated by the LLM

### 3. Sub-Agent Constraints

Each product description is generated by a separate sub-agent with strict instructions:
- Web search for real product features (snippets only, no page fetches)
- Return plain text only (no JSON structure to hallucinate)
- Word limit enforced

### 4. Synchronous Parallel Batches

Sub-agents run in synchronous batches of 5-6, returning results directly. This allows immediate verification rather than relying on background processes.

## Output

Descriptions are stored in two places:
1. **CSV column**: `amazon_reviews_..._top_products.csv` (source of truth)
2. **JSON file**: `stimuli/[column-name].json` (for experiment runtime)

The JSON is always derived from the CSV via `export`, never written directly.
